# TodoRemind

TodoRemind は、日付ごとにTODOや予定を整理し、設定した日時にリマインド通知を受け取れるWebアプリです。GitHub Pagesで公開する静的サイトを中心に、Cloudflare Workerを使ったデータ同期とWeb Push通知に対応しています。PWAとしてホーム画面に追加して利用することもできます。

## 公開サイト

https://moriwakiren-fucc.github.io/TODOWEEK/

## 主な機能

- **日付ごとのTODO管理**：タスクの作成・編集・削除、完了状態の切り替えに対応しています。
- **予定の登録**：完了チェックを付けない「予定」として登録できます。
- **ドラッグによる整理**：タスクを別の日付へ移動したり、同じ日付内で並べ替えたりできます。タッチ端末では長押しして操作します。
- **期限切れタスクの確認**：期日を過ぎても未完了のTODOを、専用の一覧で確認できます。
- **リマインド通知**：期限当日・期限の数日前・日付指定などから通知日を選び、複数の通知時刻を設定できます。
- **教科と書式のカスタマイズ**：教科の追加・削除・並べ替え、教科ごとの文字色や背景色の設定、タスクごとの文字色・背景色・下線などに対応しています。
- **お気に入り**：よく使うタスクの内容を保存し、新しいタスクの入力に再利用できます。
- **デフォルト設定**：新しいタスクを作るときの予定区分・教科・通知時刻などを設定できます。
- **週単位の目標欄**：表示を移動しながら、目標を記録できます。
- **端末間同期**：同じユーザーIDを入力した端末同士で、タスク・お気に入り・教科設定を共有できます。
- **オフライン利用**：Service Workerによる静的ファイルのキャッシュと、ブラウザー内へのデータ保存により、ネットワークがない場合も保存済みデータを表示・編集できます。クラウド同期やプッシュ通知には通信が必要です。
- **自動同期**：オフライン中に変更したタスクは、オンライン復帰後にアプリを開いたとき、またはリマインド通知を受け取ったタイミングで、アプリを開かなくても自動で同期されます（詳しくは「データ保存と同期」を参照）。
- **PWAとアプリアイコンのバッジ**：対応環境では、ホーム画面のアプリアイコンに未完了TODOの数を表示します。設定メニューの「バッジの設定」で、数える対象を「過去（今日より前）」「今日」「未来（今日より後）」から選べます（標準は過去のみ）。「予定」を含めるかどうかも選べます（標準は含めない）。完了済みTODOは数えません。バッジはアプリを開いたときのほか、リマインド通知の受信時にも更新されます。
- **アップデート情報**：`version.json` に記載された更新履歴をアプリ内で確認できます。

## 使い方

1. [公開サイト](https://moriwakiren-fucc.github.io/TODOWEEK/)を開きます。
2. 端末間でデータを共有する場合は、ユーザーIDを設定して同期を開始します。IDには英数字・ハイフン（`-`）・アンダーバー（`_`）を使用できます。複数の端末で**同じID**を入力してください。
3. 端末内だけで使う場合は、ユーザーID設定画面で「スキップ（このデバイスのみで使う）」を選びます。
4. 日付欄の追加ボタンからTODOまたは予定を作成し、必要に応じて教科・書式・リマインド通知を設定します。
5. プッシュ通知を使う場合は、設定メニューの「通知設定」から通知を有効にし、ブラウザー／OS側でも通知を許可してください。

ホーム画面への追加方法や通知機能の対応状況は、利用するブラウザー・OSによって異なります。

## データ保存と同期

| データ | 保存・同期先 |
| --- | --- |
| TODO・予定 | ブラウザー内に保存し、ユーザーID設定時はCloudflare Worker経由で同期 |
| お気に入り | ブラウザー内に保存し、ユーザーID設定時はクラウド同期 |
| 教科リスト・教科の色・バッジの設定 | ブラウザー内に保存し、ユーザーID設定時はクラウド同期（KVの `subjectSettings_` に保存） |
| デフォルト設定 | ブラウザー内のみ |
| 週単位の目標 | ブラウザー内のみ |
| プッシュ通知の購読情報 | Cloudflare Worker側に端末ごとに保存 |

オフライン中のタスク変更は端末内に保存され、オンライン復帰時に同期されます。

**同期は「タスク単位の統合」方式です。** 各タスクが更新時刻（`updatedAt`）を持ち、Worker（`PUT /tasks/:userId`）が保存済みの一覧と受け取った一覧をIDごとに比べ、更新時刻が新しい方を残します。そのため、別々の端末で別のタスクを編集・追加しても、互いに消えません。削除したタスクは「墓標」（`{id, deleted:true, updatedAt}`）として30日間クラウドに残り、他の端末から古いコピーが復活するのを防ぎます。

- 同じタスクを複数端末で編集した場合は、更新時刻が新しい方の内容が丸ごと残ります（項目単位では統合しません）。更新時刻は各端末の時計を使うため、端末の時計が大きくずれていると判定がずれます。
- 30日以上オフラインだった端末が古いコピーを持っていた場合、削除済みのタスクが復活することがあります。
- `updatedAt` を持たない旧バージョンの端末から同期した場合、その端末での削除はクラウドに反映されません（更新後の端末では正しく動作します）。

**バックグラウンド同期の仕組みと制約**

未同期の変更は、画面側がIndexedDBにも保存します。Service Workerは `localStorage` を読めないためです。リマインド通知を受信したとき、`sw.js` がこの写しをWorkerへ送って同期します。

- iPhone・iPadのPWAは、Background Sync APIに対応していません。オンラインに戻った瞬間には同期されず、**復帰後に最初に届く通知のタイミング**（またはアプリを開いたとき）に同期されます。通知を受け取る設定が前提です。
- Android（Chrome系）では、Background Syncにより復帰時に自動で同期されます。

**注意：** ローカルだけで作成したタスク（更新時刻なし）は、初めてユーザーIDを設定したときにクラウドから読み込んだ一覧で置き換わる場合があります。既存データがある場合は、同期を有効にする前に内容を確認してください。

「ログアウト」は、この端末に保存された同期IDやタスクのローカルデータをクリアしますが、Cloudflare側に保存されたデータを削除する操作ではありません。

## ファイル構成

GitHubリポジトリのルートには、次のファイルを配置します。

```text
TODOWEEK/
├── index.html              # 画面の構造
├── style.css               # デザイン・レイアウト
├── script.js               # TODO管理、同期、通知などの処理
├── sw.js                   # Service Worker（キャッシュ、プッシュ通知、バッジ）
├── manifest.json           # PWAの名前、起動URL、アイコンなど
├── version.json            # アプリのバージョン履歴
├── favicon.ico             # ブラウザー用アイコン
└── apple-touch-icon.png    # ホーム画面用アイコン
```

`worker.js` はCloudflare Worker側のファイルです。GitHub Pagesの静的ファイルとは別にデプロイします。HTML・CSS・JavaScriptはビルドツールを使わずに動作する構成です。

## 使用技術と構成

- **フロントエンド**：HTML、CSS、JavaScript
- **静的サイト公開**：GitHub Pages
- **API・データ同期・プッシュ通知**：Cloudflare Workers
- **サーバー側の保存先**：Cloudflare Workers KV
- **オフラインキャッシュとプッシュ通知の受信**：Service Worker
- **ブラウザー内の保存**：Local Storage、アプリアイコンのバッジ情報にはIndexedDBも使用
- **PWA設定**：Web App Manifest

### Cloudflare Workerの設定

`worker.js` は、次のKVバインディングと環境変数を使用します。

**KVバインディング**

| バインディング名 | 用途 |
| --- | --- |
| `TODOWEEK_KV` | TODO、予定、お気に入り、教科設定などの保存 |
| `SUBS_KV` | Web Pushの購読情報 |
| `UPDATE_KV` | 更新履歴に関する端末別の記録 |

**環境変数**

| 変数名 | 設定内容 |
| --- | --- |
| `VAPID_PUBLIC_KEY` | Web Push用VAPID公開鍵（Text） |
| `VAPID_PRIVATE_KEY` | Web Push用VAPID秘密鍵（Secretとして設定） |
| `VAPID_SUBJECT` | 通知送信者の連絡先。例：`mailto:you@example.com` |

`VAPID_PUBLIC_KEY` と `VAPID_PRIVATE_KEY` には、対になった鍵を設定してください。通知送信には、Cloudflare WorkerのCron Triggerも必要です。Worker内では日本時間（JST）を基準に5分単位で通知時刻を判定するため、5分ごとに実行する設定例は `*/5 * * * *` です。

フロントエンドの `script.js` にはWorkerのURLが定数として記述されています。現在の設定先は `https://todoweek-api2.moriwakiren-fucc.workers.dev` です。WorkerのURLを変更した場合は、`WORKER_URL` も変更してください。

## GitHub Pagesへの公開

1. 上記のフロントエンドファイルとアイコンをGitHubリポジトリのルートに配置します。
2. GitHubリポジトリの **Settings → Pages** で、リポジトリのファイルを公開する設定を行います。
3. `worker.js` をCloudflare Workersへ別途デプロイし、必要なKVバインディング・環境変数・Cron Triggerを設定します。
4. 公開URLでタスクの保存、ユーザーIDによる同期、Service Workerの登録、通知をそれぞれ確認します。

現在の設定は、リポジトリ名が `TODOWEEK` で、GitHub PagesのURLが `https://moriwakiren-fucc.github.io/TODOWEEK/` であることを前提としています。リポジトリ名や公開パスを変更する場合は、`manifest.json` の `start_url` と `scope`、および `script.js` の `VERSION_URL` なども見直してください。PWAやService Workerの動作確認は、`file://` で直接開くのではなく、HTTPSの公開環境などで行ってください。

## 更新時の注意

- 同期方式（タスク単位の統合）を使うため、**`worker.js` を先にCloudflareへデプロイし、そのあとでGitHubのファイルを更新**してください。順序が逆でも動作はしますが、Worker更新までは端末間の同時編集で変更が失われる可能性があります。
- 更新内容を `version.json` の先頭に追加します。各項目は `version`、`date`（`YYYY-MM-DD`形式）、`changes`（文字列の配列）で構成します。
- 静的ファイルのキャッシュを更新させるには、`sw.js` の `CACHE_NAME` を新しい値に変更してください。変更しないと、ブラウザーに古いファイルが残る場合があります。
- 利用者側では、設定メニューの「キャッシュをクリアして再読み込み」から再読み込みを試せます。

## セキュリティと利用上の注意

- **ユーザーIDは認証用のパスワードではありません。** 現在のWorker APIには、ユーザーIDの所有者を確認するログイン認証がありません。同じIDを知っている人は、共有データにアクセスしたり、データを変更したりできる可能性があります。推測されにくいIDを使い、個人情報や機密情報を登録しないでください。
- ユーザーIDを他の人と共有すると、その人ともデータが共有されます。
- 通知や同期が動作しない場合は、ネットワーク接続、ブラウザーの通知権限、WorkerのKVバインディング・VAPID設定・Cron Triggerを確認してください。
- アプリアイコンのバッジやプッシュ通知の利用可否は、ブラウザーとOSの対応状況に依存します。
